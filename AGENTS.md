# AGENTS.md: Лагерь у костра

Инструкции для ИИ-агентов, которые работают с кодом «Лагеря у костра» (проект Taskcraft). Файл описывает версию 1.0.0. Он должен лежать в корне репозитория рядом с `package.json`.

## Что это

Планировщик дня в духе классического фэнтези, PWA для телефона и компьютера. Задачи дня становятся спутниками у костра, жизнь делится на сферы Королевства (как колесо баланса), большие цели становятся проектами внутри сфер, просроченные задачи встают нежитью на лесной дороге. Весь день помещается на одном экране телефона, план собирается на отдельном. В Летописи лежат дневник и свои разделы с заметками, за них нет ни золота, ни опыта.

Своего сервера нет. Игра и заметки хранятся в `localStorage`, а между устройствами синхронизируются через приватный репозиторий игрока на GitHub (`lager-data`, токен только к нему с одним правом «Contents: Read and write»). В репозитории лежат `game/save.json` (сохранение, каждая запись это коммит), `notes/<раздел>/…` (заметки, файл на заметку, в `_razdel.json` название раздела) и `diary/<год>/…` (дневник, файл на день). Публичный репозиторий игра не примет: там лежит дневник.

Сайт публикуется на GitHub Pages и открыт для всех, пароля у него нет.

Правила игры подробно описаны в `README.md` (раздел «Правила»), все числа баланса лежат в `src/game/rules.ts`.

## Стек

- Preact 10 (не React) с JSX через `@preact/preset-vite`, `jsxImportSource: "preact"`. Импортируй хуки и `Component` из `preact` и `preact/hooks`, не из `react`.
- TypeScript 5.9 в строгом режиме: `strict`, `noUnusedLocals`, `noUnusedParameters`.
- Vite 7, сборка в `dist/` с `base: './'`.
- Vitest 4 для логики, Playwright 1.63 и axe-core для экранов.
- Шрифты Philosopher (заголовки, кнопки, нижнее меню) и Alegreya Sans (остальной текст) из `@fontsource`.
- Других зависимостей на сайте нет. Не добавляй новые библиотеки без явной просьбы: каждая утяжеляет офлайн-кэш и требует строки в лицензиях.
- Node.js 22.12+ (подойдёт 20.19+). Версии в `package.json` закреплены точно, без `^`.

## Команды

```
npm install
npm run dev          # http://localhost:5173, доступен и с телефона в той же сети
npm run typecheck    # tsc --noEmit
npm test             # автотесты логики (vitest), сейчас 328
npm run build        # tsc + vite build + scripts/build/finish.mjs → dist/
npm run preview      # показать собранный сайт
npx playwright install chromium   # один раз
npm run e2e          # автотесты экранов; проверяют dist/, поэтому сначала build
```

- Упавший e2e оставляет снимок и трассу в `test-results/`: `npx playwright show-trace test-results/…/trace.zip`.
- Перед тем как сдать работу, прогони `npm run typecheck`, `npm test`, `npm run build`, а если трогал экраны, ещё `npm run e2e`.
- **Пуш в `main` сразу публикует сайт** (`.github/workflows/deploy.yml`). Не пушь в `main` без прямого разрешения владельца: закоммить локально и спроси.

## Архитектура и правила кода

- **Логика отдельно от экранов.** Всё, что меняет игру, это функции над `State` в `src/game/state.ts`. Они меняют переданное состояние на месте, а `store` вызывает их на своей копии: если действие упало, игра возвращается к последней записи. В `src/game/` нет DOM и Preact, всё проверяется vitest. Новое правило сначала появляется там и в тестах, потом на экране.
- **Числа только в `rules.ts`.** Не вписывай награды, ману, сроки и пороги прямо в код экранов. «Правила» в Настройках берут числа оттуда же.
- **Слова только в `words.ts`.** Названия классов, смен, повторов, периодов и склонения живут там (словарь для разбора фраз лежит в `phrase.ts`: это не надписи, а то, что игра узнаёт); экраны берут их оттуда.
- **Время.** Игровой день начинается в 4 утра (`DAY_STARTS_AT_HOUR`). Таймер, мана и смена дня досчитываются из сохранённых моментов (`settle`), а не тиками, чтобы два устройства считали одинаково. Не заводи состояние, которое растёт от `setInterval`.
- **Формат сохранения.** Номер формата `SAVE_VERSION` в `src/game/store.ts` (сейчас 4). Если меняется устройство `State`, подними номер на один и добавь переход в `MIGRATIONS`. Если новое поле можно добавить так, что предыдущая версия откроет игру как есть, лучше обойтись без нового номера и сказать об этом в CHANGELOG. Нечитаемое или более новое сохранение никогда не затирается.
- **Слияние.** Любое новое поле `State` должно правильно сливаться в `src/game/merge.ts` при правках с двух устройств, и на это нужен тест в `tests/sync.test.ts`.
- **Летопись отдельно от игры.** Заметки и дневник не входят в `State` и в `game/save.json`, это обычные Markdown-файлы, которые можно править прямо на GitHub. Цвет текста пишется как в Obsidian: `<span style="color:#ef6b5e">текст</span>`. Если одну заметку поменяли на двух устройствах, своя версия ложится рядом отдельным файлом с припиской `-s-telefona` или `-s-kompyutera`, а день дневника сливается по записям (`mergeDiary`). «Стереть всё» убирает заметки из браузера, а `notes/` и `diary/` в GitHub не трогает. Новое поведение идёт с тестом в `tests/notes.test.ts`, оформление в `tests/markdown.test.ts`.
- **Настройки устройства** (сила магии, токен GitHub, вход в Google и OAuth-ключ, если его вписали в Настройках) не попадают ни в сохранение, ни в файлы репозитория. В сохранении лежит только id календаря «Лагерь» в Google (`State.googleCalendar`), чтобы устройства писали в один календарь.
- **Магия только догоняет игру.** Состояние меняется сразу, заклинание зовётся после. Ни одна кнопка не ждёт конца анимации, новое заклинание гасит прежнее. Слои магии не ловят нажатий и скрыты от диктора (`aria-hidden`, `pointer-events: none`). Ошибка магии пишется в консоль и не роняет игру. Учитывай три режима: «Вся», «Спокойная» (без частиц, полётов и сдвигов), «Без анимаций»; «Уменьшить движение» в системе включает спокойную.
- **Безопасность.** На странице стоит Content-Security-Policy: скрипты только свои, запросы только к своему сайту, к GitHub (`api.github.com`) и к Google Calendar API (`www.googleapis.com`); вход в Google это переход на его страницу, а не запрос. Не подключай CDN, внешние шрифты и сторонние запросы. Токен GitHub не логируй и не клади в отчёт об ошибке.
- **Облики героев.** У каждого класса пять обликов: `rogue`, `rogue-b` … `rogue-e` и так же у остальных, они описаны в `CHARS` в `scene/camp.js`. Число обликов задаёт `LOOKS` в `src/game/view.ts`, буквы в именах картинок `LOOK_SUFFIX` в `src/scene/scene.ts`. Облик задачи считает `lookOf` в `src/game/view.ts` из её `id`, картинку выбирает `heroKey` в `src/scene/scene.ts`; в сохранении облика нет. Плащ героя снимается ещё и отдельным белым слоем (`*-cape.webp`, поле `cape` в `camp.json`), `src/ui/tint.ts` умножает его на цвет похода и собирает одну готовую картинку. Новый облик или класс должен иметь плащ и все пятнадцать картинок, это проверяет `tests/looks.test.ts`.
- **Картинки лагеря** не правь руками: переснимай через `scripts/render-camp` (`npm run models`, `preview`, `render`, `icons`), камера, свет и места в `scene/camp.js`.
- **Нажатия и прокрутка.** Сама страница не прокручивается (`html`, `body` с `overflow: hidden`, у `.app` высота 100%, а не `100dvh`), листаются только разделы внутри: иначе на Android прокрутка уносит нижнее меню. Текст выделяется только в `input`, `textarea` и `contenteditable`, везде ещё стоит `user-select: none`. Задачу в лагере открывает и номер над спутником (кнопка), и нажатие на саму фигуру: `pick.ts` смотрит на непрозрачный пиксель под пальцем, а костёр закрывает тех, кто за ним. Кнопка «Назад» закрывает лист и знакомство, с других разделов ведёт в Лагерь, из Лагеря без листов выходит из приложения (`back.ts`).

## Интерфейс и тексты

- Весь интерфейс, тексты, комментарии в коде, названия тестов, CHANGELOG и README пишутся по-русски.
- Словарь мира: задача это спутник, сфера жизни (как в колесе баланса) это часть Королевства, большая цель это проект внутри сферы, просроченная задача это нежить, задача без сферы и дня это письмо вестника. Сферы и проекты лежат вместе в `State.quests` (у сферы `sphere: true`, у проекта `sphereId`), задача ссылается на любую из них через `questId`. Тип «рабочая / личная / в любое время» берётся у сферы (`kindOf`). «Костёр» значит план на сегодня, «огонь» задачу в работе («Сейчас у огня», «Оставить у костра на завтра»). Разделы: Лагерь, План (сбор отряда), Королевство, Летопись (дневник, свои разделы с заметками, поиск, «Последние дни»), Настройки (герой, распорядок, магия, сохранение в GitHub, копия в файл, справка, «Стереть всё»), Лавка (открывается золотом в верхней полосе Лагеря: награды, которые игрок заводит сам и покупает за золото, цель, история покупок). Награды лежат в `State.prizes`, покупки в `State.purchases`, цель в `State.goalId`; все три поля необязательные, пустыми не сохраняются. Золото может уйти в минус (одно золото потрачено на двух устройствах без связи или отменено уже потраченное «Готово»): это не ошибка, покупать тогда нельзя, пока новые дела его не вернут.
- Числа склоняются («21 задача», «22 письма»), фразы не зависят от пола игрока, правила на экране говорят то же, что делает игра.
- Стиль текстов простой и разговорный, без канцелярита. В README к читателю на «ты».

## Доступность

Это обязательная часть каждой правки экрана, а не доработка на потом.

- Кнопки и переключатели не меньше 44×44, контраст текста не ниже 4,5:1.
- Разделы экранов это заголовки. Значки, уровни, римские цифры и цвета диктор слышит словами («уровень 1, разбойник», «алое знамя»).
- Пока открыт лист, Tab ходит только по нему, после закрытия фокус возвращается на кнопку, которая его открыла. Если эта кнопка пропала, фокус встаёт на ближайший заголовок или кнопку (`src/ui/focus.ts`).
- Сообщения внизу экрана озвучиваются вместе с кнопкой «Вернуть».
- Новые экраны и листы добавляй в проверку axe в `e2e/a11y.spec.ts`. Для заметных изменений обнови `docs/screen-reader-check.md`.

## Тесты

- Логика: `tests/*.test.ts` на vitest. Новое правило, поле сохранения или поведение синхронизации идёт вместе с тестом.
- Экраны: `e2e/*.spec.ts` на Playwright, по-русски названные сценарии. Часы браузера ставятся через `openGame(page, { time: at(9) })` из `e2e/helpers.ts`, пояс Europe/Moscow, локаль ru-RU. GitHub в e2e поддельный, к настоящему API тесты не ходят.
- Проекты Playwright: телефон 390×844 для всего, плюс маленький телефон 360×640 для дня, компьютер 1280×800 для дня, папок Летописи и Лавки, плюс «Уменьшить движение» для дня, магии и Лавки.
- Не отключай и не пропускай тесты, чтобы стало зелёно.

## Версии и релизы

- Версия в `package.json` (сейчас 1.0.0), она видна в Настройках → «О приложении» и в отчёте об ошибке. Поднимай её в каждом релизе.
- `CHANGELOG.md` в корне репозитория, новая версия сверху: заголовок `## X.Y.Z, коротко о главном`, дальше разделы по надобности: «Игроку», «Доступность», «Сохранение», «Сайт», «Правила», «Проверки», «Прочее». Пункты пишутся для игрока, простыми предложениями. В «Сохранении» всегда сказано, менялся ли формат и откроет ли игру прошлая версия. В «Проверках» сказано, какие тесты добавлены и сколько их теперь.
- Бета-релиз выкладывается в общую папку проекта, в `lager/beta-X.Y.Z/`, тремя файлами:
  - `taskcraft-lager-X.Y.Z.zip`: весь проект в папке `taskcraft-lager/`, с `.github/`, без `node_modules/`, `dist/`, `test-results/` и других путей из `.gitignore`;
  - `izmeneniya-A-B.patch`: `git diff` от прошлого релиза (`diff --git a/… b/…`), например `izmeneniya-0.4.0-0.4.1.patch`;
  - `CHANGELOG.md`: копия файла из корня.
- Перед выкладкой релиза должны проходить typecheck, тесты логики, сборка и e2e.
- Отдельные доработки между релизами выкладываются патчем в свою папку в `lager/` (так лежат `edinoe-vremya/` и `menyu-kartinki/`), с картинкой результата, если меняется экран.

## Что ещё лежит в общей папке `lager/`

- `beta-*/`: выпущенные бета-версии. Актуальный код лежит в `main`: там могут быть правки новее последней беты.
- `app/`: ранняя копия проекта (0.1.0). Для новой работы бери код из репозитория.
- `magiya/`: отдельный прототип анимаций на чистом JS со своей сборкой (`python3 build.py`) и тестами на Playwright. Это не код приложения; магия из него перенесена в `src/ui/magic/`.
- `edinoe-vremya/`, `menyu-kartinki/`: патчи доработок.
- `screens/`: снимки экранов.
