# Лагерь у костра

Планировщик дня в духе классического фэнтези. Задачи дня становятся спутниками у костра, большие цели становятся походами на логова, а просроченные задачи встают нежитью на лесной дороге. Весь день помещается на одном экране телефона, план собирается на отдельном.

## Запуск

Нужен Node.js 22.12 или новее (подойдёт и 20.19+).

```
npm install
npm run dev
```

Откроется на http://localhost:5173. В консоли будет строка `Network: http://192.168.…:5173`: этот адрес открывается с телефона, если он в той же сети Wi-Fi. В режиме разработки пароля нет.

- `npm test` прогоняет автотесты логики: правила, день, хранение, сохранение в GitHub.
- `npm run build` собирает сайт в `dist/`, `npm run preview` показывает собранный. Без пароля сборка выходит открытой; чтобы проверить замок у себя, задай пароль перед сборкой. В PowerShell:
  ```
  $env:LAGER_PASSWORD = "пароль"; npm run build; npm run preview
  ```
  Пароль остаётся в этом окне PowerShell до его закрытия. Чтобы снова собирать без пароля, выполни `Remove-Item Env:LAGER_PASSWORD`.
- `npm run e2e` проверяет собранный сайт в настоящем браузере, подробнее ниже.

### Автотесты экранов

В `e2e/` лежат тесты, которые проходят игру так же, как человек, в Chromium через Playwright:

- день от знакомства до отбоя: задачи добавляются, костёр разжигается, задача зовётся к огню, привал, «Готово», итоги дня и утро следующего дня. Этот тест идёт на маленьком телефоне (360×640), обычном (390×844) и компьютере (1280×800);
- запуск без сети после первого визита;
- повторяющиеся задачи;
- сохранение в GitHub с поддельным GitHub: токен перестал работать, сети нет дольше часа, срок токена подходит к концу;
- «Стереть всё» с сохранением в GitHub и без;
- доступность: проверка axe на всех экранах и листах, работа с клавиатуры в листах;
- магия: нажатия посреди заклинаний, «Вернуть» посреди награды, новый уровень, нажатие под закрывающимся листом, настройка «Магия», день от разжигания до отбоя и падение логова. День и эти тесты идут ещё раз на телефоне с «Уменьшить движение» в системе;
- знамя похода: свой цвет кодом и ползунками, номера над спутниками в цвете похода;
- страница входа, если сайт собран с паролем.

Тесты проверяют то, что лежит в `dist/`, поэтому сначала нужна сборка. Браузер для них скачивается один раз:

```
npx playwright install chromium
npm run build
npm run e2e
```

Если сайт собран с паролем, тесты вводят его сами, поэтому пароль нужен и при запуске: `$env:LAGER_PASSWORD = "пароль"; npm run build; npm run e2e`.

Если тест упал, в `test-results/` остаются снимок экрана и запись прохода. Запись открывается командой `npx playwright show-trace test-results/…/trace.zip`: в ней видно каждый шаг и страницу на нём.

Как звучит игра в VoiceOver и TalkBack, автотест не проверит. Для этого есть памятка `docs/screen-reader-check.md`, проход по ней занимает минут двадцать.

## Сайт на GitHub Pages с паролем

Сайт закрыт паролем: без него открывается только страница входа. Пароль задаётся секретом в репозитории, в коде его нет.

1. Создай репозиторий на GitHub. На бесплатном тарифе Pages работает только у публичных репозиториев (подробнее про это в разделе «Что закрывает пароль»).
2. Залей проект:
   ```
   git init
   git add .
   git commit -m "Лагерь у костра"
   git branch -M main
   git remote add origin https://github.com/ЛОГИН/РЕПОЗИТОРИЙ.git
   git push -u origin main
   ```
3. Задай пароль: в репозитории Settings → Secrets and variables → Actions → New repository secret. Имя `LAGER_PASSWORD`, значение сам пароль. Пробелы в начале и в конце не считаются.
4. Включи Pages: Settings → Pages → Source: **GitHub Actions**.
5. Запусти публикацию: Actions → «Публикация» → Run workflow (первая, что запустилась при пуше, могла упасть, пока Pages и пароль не были настроены).

Дальше каждый пуш в `main` прогоняет автотесты логики, собирает сайт, проверяет его автотестами экранов и публикует по адресу `https://ЛОГИН.github.io/РЕПОЗИТОРИЙ/`. Если что-то упало, на сайте остаётся прежняя версия, а что именно упало, видно в Actions в логе шага. Если секрет `LAGER_PASSWORD` не задан, сайт публикуется открытым, а в Actions появляется предупреждение. Чтобы закрыть сайт, добавь секрет и запусти публикацию заново.

Знакомым даёшь ссылку и пароль. При входе можно отметить «Запомнить на этом устройстве», тогда пароль больше не спросят; забыть его можно в Настройках → «О приложении». Чтобы сменить пароль, поменяй секрет и запусти публикацию заново: все, кто его запомнил, введут новый, игра у них при этом не пропадёт.

На телефоне сайт стоит добавить на главный экран: в Chrome меню ⋮ → «Добавить на главный экран», в Safari «Поделиться» → «На экран Домой». Игра откроется без адресной строки, а Safari не сотрёт её через неделю без визитов. На iPhone игра сама подскажет это строкой над меню.

### Что закрывает пароль

При сборке (`scripts/build/finish.mjs`) код игры шифруется (AES-GCM, ключ из пароля через PBKDF2-SHA256, 600 000 итераций). На сайте лежит только зашифрованный файл и страница входа (`scripts/build/lock.js`): пароль превращается в ключ прямо в браузере, на сервер он не уходит.

- Закрыто: сама игра. Без пароля сайт ничего, кроме страницы входа, не показывает.
- Открыто: картинки лагеря, шрифты, иконки приложения и стили. По ним видно, как выглядит игра, но играть нельзя.
- Если репозиторий публичный, его код может прочитать любой, кто найдёт репозиторий. Данных игроков там нет: игра каждого хранится в его браузере и в его собственном приватном репозитории. Чтобы закрыть и код, нужен приватный репозиторий: на тарифе GitHub Pro Pages работает и из него. Бесплатный вариант: держать код в приватном репозитории, а собранный сайт публиковать в отдельный публичный.
- Пароль защищает от случайных людей, а не от упорного взлома: короткий пароль можно перебрать, имея зашифрованный файл. Возьми пароль из трёх-четырёх случайных слов.

## Работа без сети и обновления

После первого открытия игра работает без интернета: при установке service worker (`scripts/build/sw.js`) скачивает все файлы своей версии, около 2 МБ. Список файлов и номер версии вписываются при сборке.

Страница всегда сначала спрашивается у сети (если сеть не ответила за 4 секунды, открывается сохранённая), поэтому при перезапуске игрок получает свежую версию. Если приложение долго висит открытым, при возвращении в него игра проверяет обновления и показывает строку «Вышла новая версия» с кнопкой «Обновить».

Номер версии берётся из `package.json` и коммита. Его видно в Настройках и в отчёте об ошибке.

## Телефон и компьютер: сохранение в GitHub

Игра всегда хранится в браузере. Чтобы телефон и компьютер видели одну и ту же игру, её можно сохранять в свой приватный репозиторий на GitHub. Своего сервера у Лагеря нет.

1. Создай на GitHub приватный репозиторий `lager-data` (в игре есть ссылка, где название и «Private» уже выбраны).
2. В игре открой «Настройки» → «Сохранение в GitHub» → «Создай токен на GitHub». Откроется страница GitHub, где уже выбраны название, срок на год и единственное право «Contents: Read and write». В «Repository access» выбери «Only select repositories» и `lager-data`, внизу нажми «Generate token».
3. Скопируй токен (начинается с `github_pat_`), вставь в поле и нажми «Подключить». Если сохранения в репозитории ещё нет, игра запишет туда текущую игру.
4. На втором устройстве вставь тот же токен. Репозиторий найдётся сам: игра ищет `lager-data`, а если токен видит только один приватный репозиторий, берёт его. Если там в браузере ещё ничего не делали, игра просто возьмёт сохранение из GitHub.

Что лежит в репозитории:

```
game/save.json    сохранение Лагеря, его пишет игра
notes/<раздел>/…  заметки Летописи: файл на заметку, в _razdel.json название раздела
diary/<год>/…     дневник Летописи: файл на день
```

Каждая запись игры это коммит «Лагерь: сохранение (телефон)» или «(компьютер)», поэтому любую прошлую версию игры видно в истории файла `game/save.json`. Публичный репозиторий игра не примет: там лежит дневник.

Как это работает (`src/sync/`, `src/game/merge.ts`):

- После каждого действия игра через несколько секунд пишет сохранение в репозиторий, а при запуске, при возвращении в приложение и раз в две минуты смотрит, не сохранило ли что-то другое устройство.
- Если с прошлой встречи менялись обе стороны (например, телефон был без сети), версии сливаются: задачи и походы с обеих сторон остаются, у одной задачи разные поля берутся оттуда, где их меняли, золото, опыт и итоги дня складываются. Если одно и то же поле поменяли на обоих устройствах, остаётся то, что сделано позже.
- Запись идёт с `sha` прочитанной версии файла. Если другое устройство успело записать между чтением и записью, GitHub запись не принимает (409), и игра перечитывает, сливает и пишет ещё раз. Затереть чужую запись нельзя.
- Таймер, мана и смена дня досчитываются каждым устройством одинаково, поэтому время, начатое на компьютере, на телефоне идёт дальше, а не удваивается.
- Если в репозитории другая игра, игра спросит, какую оставить. Копия из файла («Загрузить копию») уходит в GitHub целиком, без слияния.
- Без сети игра работает как обычно, сохранение догонит, когда сеть появится.

Если сохранение не доходит до GitHub:

- Когда запись в GitHub не проходит (например, GitHub больше не принимает токен) или в репозитории ждёт другая игра, в верхней полосе лагеря появляется значок. Он открывает «Сохранение в GitHub», где сказано, что случилось и что сделать.
- Когда сети нет дольше часа, значок спокойнее: игра хранится в браузере и догонит GitHub сама.
- Срок токена игра узнаёт от GitHub, а если браузер его не видит, считает год от подключения. Его можно поправить в том же листе. За две недели до конца над меню появляется напоминание с кнопкой «Заменить».
- «Заменить токен» в листе «Сохранение в GitHub» принимает новый токен того же аккаунта GitHub, который видит тот же репозиторий. Репозиторий и игра остаются прежними.

Про безопасность:

- Приватный репозиторий видишь только ты и те, кого ты сам туда пригласишь.
- Токену доступен только выбранный репозиторий и только его файлы: ни других репозиториев, ни настроек аккаунта он не видит.
- Токен хранится только в браузере этого устройства и в копию сохранения не попадает. Пароля у него нет, поэтому на чужом компьютере GitHub лучше не подключать. Если устройство потерялось, токен отзывают на странице github.com/settings/personal-access-tokens.
- Все сайты одного аккаунта на `ЛОГИН.github.io` живут на одном адресе и видят хранилище друг друга. Не публикуй рядом чужой код, которому не доверяешь.

## Летопись: дневник, свои разделы и заметки

Во вкладке «Летопись» (и в книге у костра) есть дневник, а ещё можно завести свои разделы, например «Идеи» или «Статьи», и записывать туда что угодно. Золота и опыта за заметки нет, герой только отвечает «Записал, не потеряется».

- **Дневник.** Пишешь в поле «Как прошёл день?», запись встаёт в сегодняшний день со временем. Дни идут списком, новые сверху; рядом с датой видно, сколько в тот день сделано в игре. Запись можно поправить или удалить. День игровой: запись в час ночи попадает во вчерашний день.
- **Записать мысль.** Кнопка у костра и наверху Летописи открывает поле и выбор: дневник или раздел. По умолчанию мысль идёт туда, куда писали в прошлый раз. В первый раз сразу предлагается раздел «Идеи».
- **Раздел.** У раздела есть название, значок и вид. Лента: одно поле, запись в одно нажатие, новые сверху. Статьи: у каждой заметки заголовок и длинный текст. Раздел можно переименовать и удалить (значок карандаша в разделе).
- **Последние дни.** Сделанное за две недели теперь лежит в Летописи отдельным разделом «из игры».

Как это лежит в GitHub (`src/notes/`):

```
diary/2026/2026-11-04.md                день дневника: записи «## 08:12» и текст под ними
notes/idei/_razdel.json                 {"title": "Идеи", "icon": "bulb", "vid": "lenta"}
notes/idei/2026-11-04-0812.md           запись ленты: имя из даты и времени
notes/stati/kak-ya-planiruyu-den.md     статья: имя из заголовка, первая строка «# Заголовок»
```

- Каждая заметка это обычный Markdown-файл, его можно открыть и поправить прямо на GitHub. Папку, созданную руками в `notes/`, игра покажет разделом.
- Заметки живут отдельно от `game/save.json`: сохранение игры от них не растёт, и правка заметки на одном устройстве не спорит с игрой на другом.
- Пока GitHub не подключён, заметки хранятся только в этом браузере (`taskcraft-lager-notes` в `localStorage`). При подключении они уходят в репозиторий.
- После правки заметка уходит в GitHub через пару секунд отдельным коммитом («Лагерь: новая заметка (телефон)»). Новое с другого устройства приходит при запуске, при возвращении в приложение и раз в две минуты. Скачиваются только изменённые файлы.
- Без сети заметки ждут в браузере и уходят, когда сеть вернётся. Внизу Летописи видно, сколько ещё не в GitHub.
- Если одну заметку поменяли на двух устройствах, версия из GitHub остаётся на месте, а своя ложится рядом отдельной заметкой с припиской `-s-telefona` или `-s-kompyutera`. Ничего не теряется.
- В один день дневника пишут с обоих устройств, поэтому день сливается по записям: новые записи с обеих сторон остаются, удалённая или поправленная на одном устройстве запись не возвращается со второго. Текст в файле дня, написанный руками без «## время», тоже виден, отдельной записью без времени. Файл дня без папки года (`diary/2026-11-04.md`) читается так же.
- Удалённая заметка или раздел пропадает из папки, но остаётся в истории репозитория.
- «Стереть всё» убирает заметки из этого браузера. В GitHub они остаются, даже если вместе с игрой удаляется и сохранение.

## Сохранение в браузере

- Игра пишется в `localStorage` после каждого действия и раз в 15 секунд. Если браузер не дал записать (кончилось место, приватный режим), над меню появляется предупреждение с кнопкой «Копия».
- Если сохранение не читается (повреждено или записано более новой версией игры), игра ничего поверх него не пишет: откладывает его в `taskcraft-lager-v1.broken` и показывает экран, где можно скачать его, взять игру из GitHub, загрузить копию из файла или начать заново.
- Формат сохранения имеет номер (`SAVE_VERSION` в `src/game/store.ts`). Когда меняется устройство `State`, номер растёт на один, а в `MIGRATIONS` добавляется переход со старого формата: старые сохранения доводятся до нового при загрузке.
- Если GitHub не подключён, раз в неделю игра напоминает сохранить копию в файл.
- Если действие упало с ошибкой, недоделанное действие не сохраняется: игра возвращается к последней записи и показывает экран «Что-то сломалось» с отчётом для разработчика.
- Настройки → «Стереть игру…» убирает из этого браузера игру, заметки и токен GitHub, а по желанию и сохранение в GitHub: удаляется только файл `game/save.json`, репозиторий, заметки, дневник и история остаются. Сначала лист предлагает скачать копию в файл. Если сохранение должно уйти тоже, а GitHub не ответил, не стирается ничего. Запомненный пароль сайта остаётся.

## Правила

- **Спутники.** Каждая задача становится спутником одного из четырёх классов, по размеру: I разбойник (до получаса), II варвар (пара часов), III маг (целый день), IV рыцарь (несколько дней). Класс подбирается по оценке времени, его можно поправить при сдаче.
- **Утро.** На экране «План» собираешь отряд на день и разжигаешь костёр: +3 опыта за каждого позванного. Лягушкой дня выбирают самую тяжёлую задачу: опыт за неё удваивается, а начать день лучше с неё.
- **День.** Позванный к огню спутник работает, таймер идёт в задачу. «Готово» даёт 25 золота за уровень и опыт (25, 40, 60, 85 по уровням), а логову похода урон, равный уровню. Когда в походе не остаётся открытых задач, логово падает, и поход можно отправить в зал трофеев.
- **Мана.** Мана показывает силы героя. Утром её 100. Работа тратит 15 в час, привал возвращает 30 в час, задача из другого похода стоит 5. Вечером или в выходной, если сегодня уже была работа, раз в день можно взять второе дыхание: +30.
- **Смены.** Утро, рабочий день, вечер, выходной и ночь (за 30 минут до отбоя). Днём на первом месте рабочие походы, вечером и в выходной личные. Распорядок меняется в Настройках.
- **Нежить.** Просроченная задача встаёт нежитью на лесной дороге: скелет-миньон с первого дня, разбойник с третьего, воин с седьмого, маг с четырнадцатого. «Упокоить» значит сделать её.
- **Вестник.** Задача без похода, без дня и без горизонта приходит к вестнику письмом. Письма разбирают в сборе отряда: задаче выбирают поход и зовут её на сегодня или в отряд.
- **Горизонты.** Задачу можно поставить на неделю, месяц, квартал или год. В сборе отряда у каждого горизонта своя вкладка рядом с «Днём»: задачи периода, сколько из них сделано, свёрнутые задачи меньших периодов внутри, стрелки к соседним периодам. Неделя считается с понедельника, а неделя на стыке месяцев относится к месяцу своего четверга. Не сделанная за период задача нежитью не становится: она остаётся хвостом, и в сборе отряда её переносят в нынешний период, в период побольше или отпускают.
- **Задача одной фразой.** В новой задаче можно написать всё сразу: «завтра в 19:00 позвонить маме», «отчёт до пятницы на 2 часа #работа», «Добавь задачу на неделю "Съесть мороженое"». Игра без всякого ИИ ищет знакомые слова: день («сегодня», «завтра», «в пятницу», «через 3 дня», «20 ноября»), срок («до пятницы», «к 15.11», «до конца месяца»), время («в 19:00», «в 8 вечера»), оценку («на полчаса», «на 2 часа», «на весь день»), горизонт («на неделю», «в декабре», «в первом квартале», «на год») и поход («#работа», «в поход Дом»). Что узнано, видно под полем. Выбранное руками сильнее фразы, а название в кавычках берётся как есть. Словарь лежит в `src/game/phrase.ts`.
- **Повторяющиеся задачи.** Задача может повторяться каждый день, по рабочим дням из распорядка или раз в неделю. В свои дни она сама встаёт в план. Пока прошлая не сделана, новая не приходит, а отпущенная вернётся в следующий свой день. Логово похода повторяющиеся задачи не ранят: они не кончаются.
- **Отпустить.** Задача уходит без награды и без штрафа. Сразу после этого её можно вернуть кнопкой «Вернуть» в сообщении внизу, позже в Королевстве → «Отпущенные».
- **Забытый таймер.** Если 90 минут не заглядывать в игру, таймер встанет сам и спросит, шла ли работа.
- **Отбой.** Перед отбоем лагерь подводит итоги дня: отмеченные задачи остаются у костра на завтра, остальные возвращаются в отряд. Игровой день начинается в 4 утра, поэтому работа после полуночи идёт в тот же день.

Все числа лежат в `src/game/rules.ts`.

## Магия

Анимации в духе волшебства. Игра меняется сразу, магия только догоняет её светом: ни одна кнопка не ждёт конца заклинания, а новое заклинание гасит хвост прежнего за 0,16 секунды. Ошибка внутри магии пишется в консоль и не роняет игру.

- Настройки → «Магия»: «Вся», «Спокойная» (без частиц, полётов и сдвигов, только мягкий наплыв) или «Без анимаций». Пока ничего не выбрано, решает система: при «Уменьшить движение» магия спокойная. Выбор лежит в настройках устройства (`taskcraft-lager-device`) и в сохранение игры не попадает.
- Слои магии поверх приложения не ловят нажатий и скрыты от экранного диктора. Числа наверху (золото, уровень, мана) магия только на время показывает прежними, пока до них летят монеты и звёзды, а настоящее значение всегда в разметке.
- Что есть: искра под пальцем, листы, смена разделов, цена смены похода, «Позвать к огню», «Готово», привал, новый уровень, искры над костром и светлячки ночью; разжигание тлеющего лагеря, нежить встаёт и упокаивается, письмо вестника, новый спутник, «Отпустить» и «Вернуть», Второе дыхание, вечер и ночь наплывом, отбой, падение логова и печать на странице пароля.

## Картинки лагеря

Лагерь нарисован заранее: 3D-сцена из моделей KayKit снимается в картинки для дня, вечера и ночи, а каждая фигура на каждом месте отдельной картинкой с прозрачным фоном. На телефоне нет 3D, поэтому всё работает быстро и не сажает батарею.

Переснять (нужен git и Chrome или Edge):

```
cd scripts/render-camp
npm install
npm run models     # скачивает модели KayKit в kaykit/
npm run preview    # три пробных кадра в out/
npm run render     # картинки в public/camp/ и src/scene/camp.json
npm run icons      # значки приложения из ночного костра
```

Камера, свет, места и позы задаются в `scripts/render-camp/scene/camp.js`.
